# 项目需求说明

本文档由项目根目录 `history_agent.md` 转换整理而来，用于描述当前系统应满足的业务能力、处理规则、配置约束和交付要求。若本文档与 `docs/01_ARCHITECTURE.md`、`docs/02_DECISIONS.md` 存在冲突，应先提交审查，不应直接修改实现。

## 1. 项目目标

本项目用于批量清洗、合并和分析财付通交易流水数据，并输出结构化 Excel 文件。系统应能递归读取案件目录中的 `TenpayTrades.txt`，完成字段清洗、金额转换、时间拆分、交易方向拆分、去重、分类识别和多工作表输出。

系统还应支持读取 `TenpayRegInfo.txt` 注册信息文件，提取账户状态、身份信息、注销或变更记录，并输出独立 Excel。

## 2. 运行入口

系统应提供以下入口：

- 单批次交易流水清洗：`python scripts/app.py -s <数据源目录> -o <输出目录> [-n 文件名]`
- 多批次结果合并：`python scripts/app_merge.py -i batch1.xlsx batch2.xlsx -o merged.xlsx`
- 注册信息提取合并：`python scripts/app_reg.py -s <数据源目录> -o <输出目录> [-n 文件名]`
- 桌面 GUI：`python scripts/gui_app.py`

GUI 应基于 pywebview 与本地 React 静态文件运行，不依赖外部 CDN。

## 3. 输入数据

### 3.1 交易流水

系统应递归扫描输入目录树中的 `TenpayTrades.txt` 文件。文件通常为 UTF-8 编码、Tab 分隔，但读取逻辑应具备编码检测能力，并跳过空文件。

系统只应处理原始 `.txt` 文件，不应把源目录中的 `.xlsx` 当作原始交易流水输入。

### 3.2 注册信息

系统应递归扫描输入目录树中的 `TenpayRegInfo.txt` 文件，并支持以下格式：

- 基本信息表：账户状态、账号、注册姓名、注册时间、注册身份证号、绑定手机、绑定状态、开户行信息、银行账号。
- 注销或变更信息表：账号、注册姓名、注册身份证号、注册时间、注销时间、开户行信息、银行账号、绑定时间、解绑时间。
- 银行卡扩展行：前若干列为空，仅补充银行卡相关信息。
- 特殊状态行：例如“账号 XXX 不存在”。

## 4. 核心处理需求

### 4.1 自适应列识别

腾讯返回字段名称和顺序可能变化，系统不应依赖固定列序号。核心字段应通过关键词组合匹配定位。

示例：

- 包含“交易”“金额”“分”的列可识别为交易金额分列。
- 包含“交易”“用途”“类型”的列可识别为交易用途类型列。

新增派生列的插入位置应基于语义锚点，而非硬编码索引：

- 日期、时间列插入到交易用途类型之后。
- 进账金额、出账金额插入到交易金额元列附近。

### 4.2 交易流水清洗

系统应对交易流水执行以下处理：

- 清洗列名和特殊 Unicode 字符。
- 合并重复列。
- 将金额从“分”转换为“元”，余额列也应转换。
- 将交易时间拆分为日期和时间。
- 将日期格式统一为类似 `2026/4/2` 的形式。
- 按借贷类型拆分进账金额和出账金额。
- 根据配置生成时段分类。
- 根据日期生成工作日、周末、节假日分类。

处理函数应保持幂等：当目标派生列已存在时，应避免重复插入或重复计算导致列膨胀。

### 4.3 去重

系统应优先使用以下字段组成联合主键去重：

- 用户ID
- 交易单号
- 大单号
- 日期
- 时间
- 借贷类型
- 交易金额(元)
- 对手方ID

加入“对手方ID”是为了避免群红包场景下误删不同收款人的记录。若部分字段缺失，应从去重键中排除并记录告警；若全部字段缺失，应降级为全列去重。

### 4.4 时段分类

系统应根据配置文件 `scripts/config/time_period_config.json` 对时间列进行时段分类。

要求：

- 支持 `HH:MM` 和 `HH:MM:SS`。
- 自动将中文全角冒号转换为半角冒号。
- 按配置顺序匹配，满足 `start <= 时间 < end` 的第一个时段即为结果。
- 未命中时返回“未知”。
- 默认时段包括凌晨、早上、下午、晚上。

### 4.5 日期分类

系统应根据 `chinesecalendar` 判断日期类型：

- 法定节假日输出 `节假日（节日名称）`。
- 调休上班日输出 `工作日`。
- 普通周六日输出 `周末`。

系统应缓存唯一日期的分类结果，避免对大数据量逐行重复计算。

### 4.6 停车缴费识别

系统应在去重后识别停车缴费记录，并输出独立工作表“停车缴费”。

识别规则：

- 备注2或备注1包含配置中的停车关键词，且不包含排除词。
- 或对手侧账户名称包含“停车”。

车牌提取规则：

- 优先从备注2提取，失败再从备注1提取。
- 支持“省份简称 + 字母 + 5 到 6 位字母数字”的车牌格式。
- 允许中间出现 `-`。
- 无法识别时填“无”。

标黄复核规则：

- 车牌为“无”。
- 且备注中包含省份简称，说明疑似存在未成功提取的车牌。

配置文件为 `scripts/config/parking_config.json`。

### 4.7 特殊交易筛选

系统应在去重后筛选特殊交易，并输出独立工作表“特殊交易”。满足任一条件即命中：

- 日期为 2 月 14 日，且配置启用该规则。
- 交易金额元格式化为两位小数后包含配置中的金额模式。
- 备注2包含配置中的特殊关键词。

配置文件为 `scripts/config/special_filter_config.json`。

### 4.8 疑似麻友识别

系统应在去重后识别疑似麻友，并输出独立工作表“疑似麻友”。

识别条件：

- 时间在 20:00 至次日 06:00。
- 交易用途类型为“转账”。
- 备注1为“微信红包”或“微信转账”。
- 对手方应通过商户关键词排除后视为自然人。
- 同一晚间 session 内发送方与配置范围内数量的不同对手方交易。
- 同一对手方在不少于配置天数的不同晚间出现。

系统应输出交易明细和总体统计，并给出高、中、低嫌疑等级。

配置文件为 `scripts/config/mahjong_config.json`。

### 4.9 群红包识别

系统应识别同一时刻向多人发出的微信红包，并输出：

- “群红包记录”
- “群红包-统计”

识别条件：

- 备注1等于“微信红包”。
- 出账金额大于 0。
- 同一日期和时间下至少出现两条记录。
- 对手方接收金额小于出账金额。

统计表应按对手方汇总收款次数和接收金额累计。

### 4.10 停车地点 AI 识别

GUI 应支持可选启用停车缴费地点识别。启用后，系统使用用户输入的 DeepSeek API Key，从停车缴费记录的备注2中提取地点并写入“地点”列。

约束：

- API Key 仅保存在内存中，不应持久化。
- 已有非“无”的地点值不应被覆盖。
- 多批次合并时，应优先复用既有文件中的地点映射。
- 调用失败时不应中断主清洗结果输出，应提供错误信息。

### 4.11 注册信息处理

注册信息处理应输出三个工作表：

- “注册信息汇总”：按账号和身份证号去重的主记录，包含数据来源和调证编号。
- “变更记录”：身份变更或账户注销历史，包含当前身份与旧身份对照。
- “基础信息”：从汇总表抽取的自然人基础信息。

银行账号相关字段不参与合并清洗，应直接透传。

GUI 单批次清洗页应提供“同时清洗注册信息”能力，并复用交易流水的输入输出路径。

## 5. 输出要求

交易流水输出 Excel 至少应包含：

- “财付通交易汇总”
- “停车缴费”（存在命中记录时）
- “特殊交易”（存在命中记录时）
- “疑似麻友”（存在命中记录时）
- “群红包记录”（存在命中记录时）
- “群红包-统计”（存在命中记录时）

Excel 输出应满足：

- 表头冻结。
- 列宽自适应。
- 敏感或冗余列默认隐藏，例如交易单号、大单号、银行卡号等。
- 用户ID、对手方ID等关键短列可使用固定列宽。
- 辅助列应隐藏。

## 6. 配置要求

配置文件统一放在 `scripts/config/` 下，当前包括：

- `parking_config.json`
- `time_period_config.json`
- `special_filter_config.json`
- `mahjong_config.json`

GUI 应能读写主要业务配置。配置读取应兼容开发环境和 PyInstaller 打包环境。

## 7. 打包要求

系统应支持 Windows PyInstaller 打包。打包时需要包含：

- `scripts/config`
- `scripts/utils`
- `scripts/webui/static`
- pywebview EdgeChromium 相关 hidden import
- tkinter 相关 hidden import

版本号应由 `scripts/version.py` 统一提供，CLI、GUI、前端展示和打包说明不应各自维护互相冲突的版本号。

## 8. 非功能需求

- 应优先使用 pandas 向量化处理，避免大数据量逐行 `apply`。
- 关键降级路径应记录日志或告警。
- 大模型地点识别应分块并发，且不能影响主流程基础输出。
- GUI 需在国内网络环境可用，不依赖 CDN。
- 输出文件编码和文本处理应使用 UTF-8。
- 对敏感字段应默认隐藏，但不应删除原始字段。

## 9. 验收标准

一次完整交付应满足：

- CLI 单批次清洗可读取目录树内多个 `TenpayTrades.txt` 并输出 Excel。
- CLI 多批次合并可合并多个历史 Excel 并正确去重。
- CLI 注册信息处理可生成三工作表 Excel。
- GUI 可完成单批次清洗、多批次合并、注册信息清洗和配置读写。
- 停车缴费、特殊交易、疑似麻友、群红包识别均在单批次和合并流程中保持一致。
- PyInstaller 打包后的 exe 能加载静态前端与配置文件。
- 文档、版本号和实际行为保持一致。

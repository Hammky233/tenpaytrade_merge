# 实现计划 — T012

## 任务 ID

T012

## 目标

在 GUI 新增“特殊交易”配置页，使用户可以分别调整特殊日期、特殊金额、特殊备注和对手侧账户名称四类筛选规则，并将配置持久化到现有用户配置目录。

## 实现范围

- 扩展 `special_filter_config.json`，为四类规则增加独立启用开关和配置列表。
- 在核心筛选模块中规范化新旧配置，保持旧版 `启用2月14日` 配置兼容。
- 金额、备注和对手侧账户名称均使用字面量包含匹配；四类规则保持 OR 关系。
- 在配置服务和 pywebview Bridge 中增加特殊交易配置读写 API。
- 在 React GUI 中增加四类规则的编辑、校验、保存与重新加载能力。
- 更新需求、任务、README、CHANGELOG 和相关自动化测试。

## 接口与配置

新增 Bridge/服务接口：

- `get_special_filter_config() -> dict`
- `save_special_filter_config(config) -> "ok" | 错误信息`

配置字段：

- `启用特殊日期: bool`
- `特殊日期: list[str]`
- `启用特殊金额: bool`
- `金额模式: list[str]`
- `启用特殊备注: bool`
- `备注关键词: list[str]`
- `启用特殊对手方: bool`
- `对手侧账户名称关键词: list[str]`

## 兼容与校验

- 旧配置中的 `启用2月14日` 转换为新日期开关，日期列表默认为 `02-14`。
- 旧配置缺少金额、备注开关时，根据对应列表是否为空推导。
- 旧配置缺少对手方规则时，默认关闭且列表为空。
- 日期接受 `M-D` 或 `MM-DD`，保存时规范化为 `MM-DD`。
- 启用的规则至少包含一个有效条目；空白和重复条目在保存前处理。
- 打包环境继续写入 `%APPDATA%/tenpaytrade/config/`，不引入新的持久化机制。

## 测试策略

- 核心筛选覆盖四类规则单独命中、OR 命中、开关关闭、字段缺失和字面量匹配。
- 配置服务覆盖新配置保存读取、非法配置拒绝、日期规范化和旧配置迁移。
- 前端完成 esbuild 构建，确认 `static/app.js` 与 JSX 源码同步。
- 运行专项测试、Python 编译检查和完整 pytest 回归。
